# Documentación do proxecto

Explica as decisións que permiten entender o problema, seguir o traballo e
comprobar o resultado. Non se trata de escribir unha memoria longa nin de
contestar un cuestionario: selecciona o relevante para o teu proxecto.

## Como usar os apartados

1. Le o bloque de instrucións visible ao comezo de cada arquivo.
2. Escribe a túa resposta en **Desenvolvemento** ou completa a ficha de alcance.
   Podes combinar texto breve, táboas, diagramas e ligazóns ás evidencias.
3. Actualiza os apartados ao tomar decisións, probar unha versión ou cambiar
   o plan. Documentación e código evolucionan xuntos.
4. Retira os bloques de instrucións e os exemplos cando completes o apartado.
   Son orientacións de traballo, non texto para copiar na entrega.

Os exemplos indican **accións posibles**, non respostas modelo, funcionalidades
adicionais nin probas obrigatorias para todos os proxectos. A
[rúbrica común](../modulo/rubrica.md) é a referencia de avaliación.

## Editar para deixar o que importa

**O límite é un exercicio de selección e edición, non un obxectivo de
extensión.** É doado xerar moito texto; unha boa documentación conserva
o que outra persoa necesita para entender as decisións, executar a solución
e comprobar os resultados.

Un proxecto completo non necesita unha explicación longa de todo o que
fixeches. Prioriza a información necesaria e importante, enlaza as evidencias
e elimina introducións xenéricas, repeticións e afirmacións que non achegan
valor. Non recortes tanto que desaparezan as xustificacións ou os pasos
necesarios para revisar o traballo.

Antes de entregar, pregúntate:

- ¿Esta información axuda a entender unha decisión, executar algo ou comprobar
  un resultado?
- ¿Estou repetindo información que xa está noutro apartado e podo enlazar?
- ¿Podo quitar ou reformular esta frase sen perder información útil?

## Que conta no límite

- Conta o texto propio das respostas, incluído o das táboas.
- Non contan este índice, os títulos e campos herdados, os bloques de
  instrucións nin os exemplos da plantilla.
- Imaxes, diagramas, código, datos de proba e comandos executables quedan
  fóra, pero non se poden usar para ocultar prosa ou engadir unha memoria.
- A síntese queda fóra do cómputo de palabras e conserva o seu máximo de
  dúas páxinas en PDF.

As instrucións técnicas van en `proyecto/README.md`; aquí enlázanse, non se
duplican. Os formatos, as revisións e a entrega explícanse na
[guía do proxecto](../modulo/guia.md).
